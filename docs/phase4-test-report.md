# Phase 4 验证报告

日期：2026-09-13

## 交付范围

- 独立计分引擎：只接收冻结周期快照和已采用槽位判定，不依赖前端、SQLite 查询细节或 OMR 阈值。
- SQLite schema v8：入账批次、账本流水、反向流水、精确正背面识别版本来源和报告导出记录。
- 整张纸表原子入账：正反面都必须为“已复核”或“确认空白”，任一侧缺失时拒绝。
- 幂等防重：同一请求重试和使用不同请求键重复点击都返回当前有效批次，不重复记分。
- X 与空白不产生流水；两种单斜线均按一次计分；跳格不影响后续有效格。
- 显式撤销：不删除原批次，创建逐条关联的负数流水并保存原因；撤销后可采用新版本再入账。
- 周期状态闭环：进行中 → 待结算 → 已关闭；未使用纸表必须显式作废，未完成纸表阻止关闭。
- 关闭后只读；维护入口填写原因重新打开后才可撤销、复核、重新入账和再次关闭。
- 结果版本：每次成功关闭递增，旧报告文件不被新版本覆盖。
- 统计接口和教师界面：个人总分、加扣分、小组人数/总分/均分/排名、项目次数/金额、账本和扫描证据入口。
- 两种报告：A4 横向教师存档版、16:9 教室展示版；关闭前只能生成带“未结算草稿”水印的预览。
- 教师版包含个人与项目明细、纸表/批次/正背面识别版本、备注；展示版不突出个人扣分或倒数排名。
- 报告明确说明没有逐事件日期，不把扫描、入账或备注录入时间伪装成事件发生日期。

## 关键验收证据

- 两张纸表累计：同一学生三次有效斜线累计为 15 分，X 和空白不计分。
- 重复点击：相同或不同幂等键重复提交同一已入账纸表，批次 ID 不变。
- 事务失败：测试触发器在写账本时强制失败；批次、流水、纸表状态全部回滚。
- 撤销：原流水保留，反向流水保存 `source_entry_id`，汇总回到撤销前基线；再入账后只计算新有效批次。
- 来源追溯：每个入账批次冻结正面/背面采用的识别版本；账本项保留有效槽位 ID 列表。
- 关闭保护：存在未入账且未作废纸表时拒绝关闭；显式作废后成功关闭。
- 维护纠错：关闭后复核和追加备注被拒绝；填写原因重新打开后可撤销、再入账，下一次关闭版本从 1 递增至 2。
- 报告一致性：报告由同一账本汇总对象生成；相同数据重复导出返回同一导出记录和相同 PDF 内容。

## 边界说明

- 当前自动测试使用程序生成纸表和确定性模拟判定，验证的是计分、事务、来源与报告一致性。
- 真实纸笔 OMR 的识别准确率仍需真实打印扫描集验收；这不影响本阶段账本对“已人工确认结果”的可靠处理证明。
- 无 Python/Node 的 macOS/Windows 双击安装包属于 Phase 5。
