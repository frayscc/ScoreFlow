# 工程决策

## D001 单仓库与同源服务

- 状态：已采用
- 决策：React 静态产物由 FastAPI 同源提供；开发时 Vite 仅绑定回环地址并代理 API。
- 理由：生产包不依赖 CDN，减少本地跨域面；浏览器界面和 Python 引擎仍能独立测试。

## D002 运行时兼容范围

- 状态：已采用
- 决策：源码最低兼容 Python 3.9，发布构建目标使用 Python 3.11；前端使用 Node 20+ 构建，Node 不进入最终用户运行环境。
- 理由：当前开发机系统 Python 为 3.9，同时为原生依赖和长期维护保留较新的发布运行时。

## D003 模板坐标

- 状态：已采用
- 决策：所有几何参数以毫米为源数据；PDF 坐标与栅格图坐标均由 manifest 明确记录，布局哈希使用规范化 JSON 计算。
- 理由：避免 PDF 绘制与识别 ROI 分别维护造成漂移。

## D004 首轮 OMR 分类

- 状态：已采用（技术样机）
- 决策：模板差分后使用墨迹占比、两条对角线响应与交叉证据分类为空白、斜线、X、待复核；低置信度不自动记为空白。
- 理由：可解释、可用模拟样本回归，真实阈值必须等实扫样本后校准。

## D005 字体

- 状态：已采用
- 决策：随包携带并嵌入 Noto Sans SC 可变字体，许可证为 SIL Open Font License 1.1；不依赖操作系统字体或网络字体。
- 理由：纸表必须离线显示中文，且字体需要具备明确的再分发授权。

## D006 班级与周期标题

- 状态：已采用
- 决策：班级名称和周期显示名都是业务数据，由用户在系统中填写；周期显示名接受“第1周”“第1—2周”等自然文本，不从日期擅自推算。
- 理由：周次由学校校历决定，日期不能可靠换算成教学周。

## D007 小组视觉分隔

- 状态：已采用
- 决策：组内学生行使用细线，每七人组边界使用贯穿“小组”合并列的加粗横线。
- 理由：保留合并组别栏，同时让纸面登记者能快速辨认相邻小组。

## D008 可变组数与人数

- 状态：已采用（用户确认调整原 7 组约束）
- 决策：项目由教师设置 1—20 个组，各组人数可以不同；纸表按实际分组边界合并和分隔。当前 A4 V1 模板最多容纳 49 名学生，超出时拒绝生成并明确提示，不自动缩小、拆页或改变纸张。
- 理由：系统需要适配其他教师的班级；49 人仍是首版纸表的最大容量和主要验收基准。
